# دایرا کلود | هسته مستقل SaaS

داشبورد فارسی و واکنش‌گرا بر پایه Next.js 16، React 19 و PostgreSQL برای مدیریت چند فضای کاری و صدور مجوز دسترسی محصولات مستقل. دیتابیس و Worker قابل انتقال از Vercel/Neon به سرور شخصی و Docker هستند.

> **دامنه کار:** این مخزن *پلتفرم مرکزی مدیریت SaaS* است؛ پیاده‌سازی خود محصولات CRM، مدیریت پروژه، ERP، رزرو و مالی در مخازن جداگانه انجام می‌شود. ادغام آن‌ها با هسته از طریق API مجوز و توکن اتصال یک‌بارمصرف پیش‌بینی شده است. هیچ عملیات مالی بدون تأیید واقعی درگاه «موفق» نمایش داده نمی‌شود.

## امکانات

- ثبت‌نام، ورود با ایمیل و رمز، هش امن scrypt، نشست HttpOnly و خروج از همه دستگاه‌ها
- بازیابی رمز و تأیید ایمیل با لینک‌های یک‌بارمصرف **پس از اتصال سرویس ایمیل**؛ ورود و تأیید شماره با OTP **پس از اتصال پیامک**
- چندفضای‌کاری مستقل، تیم، نقش‌های owner/admin/manager/member/viewer، دعوت با لینک دارای انقضا و **شرط تأیید ایمیل دعوت‌شونده**
- ثبت اشتراک آزمایشی ۱۴روزه، پلن رایگان و پولی، سهمیه کاربران/API/محصول، لغو دوره‌ای و انتقال به پلن رایگان با Maintenance
- پیش‌فاکتور، فهرست صورتحساب، کد تخفیف، دفتر اعتبار، گزارش درآمد و اتصال اختیاری زرین‌پال با تأیید سروری پرداخت
- کلیدهای API فقط یک‌بار قابل مشاهده، هش‌شده در پایگاه‌داده، محدودیت درخواست، idempotency و استفاده ماهانه
- Webhook امضاشده با HMAC-SHA256، DNS/IP validation، قفل پردازش، retry و Worker مستقل
- API مجوزدهی برای محصولات و توکن دو‌دقیقه‌ای یک‌بارمصرف برای اتصال نرم‌افزارهای مستقل
- دامنه اختصاصی با بررسی مالکیت TXT (اتصال نهایی DNS/TLS بر عهده زیرساخت استقرار)، اعلان‌ها، لاگ فعالیت، تیکت و پاسخ پشتیبانی
- پنل مدیریت مرکزی برای مشاهده مشترکان، اشتراک‌ها، درآمد تأییدشده، تخفیف، اطلاعیه، تیکت و تعلیق دسترسی
- صادرات CSV داده‌های همان فضای کاری، PWA پایه و رابط فارسی راست‌به‌چپ

## راه‌اندازی

Node.js 22+ و PostgreSQL 14+:

```bash
cp .env.example .env.local
npm install
npm run db:migrate
npm run dev
```

مقدار واقعی `DATABASE_URL` و `APP_SECRET` را در `.env.local` قرار دهید؛ `APP_SECRET` باید رشته تصادفی دست‌کم ۳۲ بایتی باشد. برای راه‌اندازی برنامه‌نویسی، اتصال پیامک، ایمیل یا درگاه *اجباری نیست*. تمام قسمت‌هایی که نیازمند این سرویس‌ها هستند تا دریافت تنظیمات، خطای مشخص برمی‌گردانند.

### سرویس‌های قابل اتصال در آینده

| سرویس | متغیرهای محیطی | رفتار بدون سرویس |
|---|---|---|
| پیامک | `SMS_HTTP_ENDPOINT`, `SMS_HTTP_TOKEN` | فرم SMS مخفی، API ارسال 503 |
| ایمیل | `MAIL_HTTP_ENDPOINT`, `MAIL_HTTP_TOKEN` | بازیابی/تأیید ایمیل غیرفعال |
| زرین‌پال | `PAYMENT_PROVIDER=zarinpal`, `ZARINPAL_MERCHANT_ID` | صورت‌حساب در `pending` باقی می‌ماند |
| Cron Vercel | `CRON_SECRET` | مسیر زمان‌بندی 401 می‌دهد |

آداپتورهای پیامک و ایمیل فعلاً HTTP POST با `Authorization: Bearer` هستند؛ قرارداد JSON آن‌ها در `lib/providers.js` مشخص است. پس از انتخاب سرویس ایرانی ممکن است به آداپتور همان سرویس نیاز باشد؛ قرار نیست با قراردادن نام کاربری جعلی، تحویل پیام موفق گزارش شود. زرین‌پال تنها در صورت فراخوانی موفق `verify` سمت سرور وضعیت صورتحساب را `paid` می‌کند. فعال‌سازی حساب‌ها باید پیش از ورود مشتریان عمومی با سرویس ایمیل واقعی همراه باشد.

## تست‌ها و CI

```bash
npm run check
npm test
npm run build
```

`GitHub Actions` روی هر PR و push به `main` اجرای بررسی نحوی، آزمون‌ها و بیلد را بررسی می‌کند. تست‌های واحد جایگزین آزمون همزمانی، امنیت عملیاتی، تست واقعی درگاه و بررسی DNS نیستند.

## API اتصال محصولات

- `GET /api/health` — سلامت PostgreSQL و اپلیکیشن
- `GET /api/app` و `POST /api/app` — عملیات داشبورد با نشست مرورگر و کنترل نقش
- `POST /api/account` — بازیابی رمز و تأیید ایمیل
- `POST /api/sms` — درخواست و تأیید کد برای ورود/تأیید موبایل (تنها با سرویس‌دهنده)
- `GET /api/v1/licensing?product=crm` — بررسی دسترسی محصول با کلید Bearer شامل scope مجوز
- `POST /api/v1/integrations/exchange` — مصرف یک‌بارمصرف توکن اتصال دو‌دقیقه‌ای
- `POST /api/v1/usage` — ثبت مصرف با کلید API و هدر اجباری `Idempotency-Key`
- `GET /api/export?workspace=<UUID>&type=...` — خروجی داده‌های همان فضای کاری با کوکی نشست
- `GET /api/admin` — گزارش تجمیعی برای مدیر کل ثبت‌شده در جدول `platform_admins`
- `GET /api/cron/maintenance` — با `Authorization: Bearer <CRON_SECRET>` برای Vercel Cron

کدهای API در `app/api/` و مدل داده و migrations در `database/` قرار دارند. برای منصوب‌کردن اولین مدیر کل، پس از ایجاد حساب با ایمیل و اتصال دیتابیس، دستور `node scripts/grant-admin.mjs email@example.com` را در محیط امن سرور اجرا کنید. این عملیات نباید به endpoint عمومی تبدیل شود.

## استقرار Docker و انتقال از Vercel

```bash
cp .env.example .env
# POSTGRES_PASSWORD, APP_SECRET, NEXT_PUBLIC_APP_URL را با مقدار واقعی پر کنید.
docker compose up -d --build
```

Compose شامل پایگاه‌داده PostgreSQL، migrator، اپ Next.js و Worker مستقل است. در استقرار ابری Vercel، Cron روزانه کار Maintenance و تخلیه بخشی از صف Webhook را انجام می‌دهد؛ برای حجم بالا Worker دائمی VPS و صف مدیریت‌شده مناسب‌تر است.

برای مهاجرت: `pg_dump -Fc` از دیتابیس مبدا و `pg_restore` روی PostgreSQL مقصد؛ سپس `DATABASE_URL` را تغییر دهید و **همان APP_SECRET** را حفظ کنید تا داده‌های رمزنگاری‌شده قابل خواندن بمانند. Worker، کارهای زمان‌بندی، HTTPS، بکاپ/بازیابی، پایش و تنظیم DNS را در سرور جدید برقرار کنید. هیچ بخش برنامه به API اختصاصی Neon وابسته نیست.

## محدودیت‌ها و شرط انتشار عمومی

- سرویس‌های SMS، ایمیل، دامنه DNS/TLS و درگاه هنوز بدون اعتبارنامه فعال نیستند، اما اتصال‌دهنده‌هایشان در کد وجود دارند.
- تمدید کاملاً خودکار پولی، ریفاند، انتقال خودکار پرداخت‌های بانکی، عملیات تطبیق حساب، و صورتحساب حقوقی/مالیاتی به قرارداد/سرویس خارجی و آزمون بیشتر نیاز دارند.
- پلن دارای `storage_mb` است اما هنوز به یک سرویس آپلود واقعی متصل نشده؛ نباید ادعای محدودیت واقعی مصرف فضای ذخیره‌سازی شود.
- API licensing، جایگزین احراز هویت مستقل محصولات متصل نیست. مصرف‌کننده این API باید tenant و scope خود را کنترل کند.
- قبل از فروش عمومی، تست بار، بازیابی فاجعه، مانیتورینگ، rate limits مرزی، ضدسوءاستفاده، اخذ رضایت کاربران و متن قانونی بر اساس کشور سرویس‌دهی مورد نیاز است.

**امنیت:** هیچ `DATABASE_URL`, `APP_SECRET`, رمز سرویس‌دهنده یا توکن دسترسی را در Git قرار ندهید. مخزن عمومی است. برای توسعه و CI از داده‌های آزمایشی مجزا استفاده کنید.
